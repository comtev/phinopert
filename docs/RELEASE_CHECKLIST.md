# Before public release

This repository is a preparation snapshot, not an arXiv submission or a claim
that every verification layer is complete.

- [x] Separate scholarly attribution and third-party rights from those grants.
- [x] Provide exact data/checker inventories and explicit computational trust.
- [ ] Review the latest paper and proof status before changing visibility.
- [ ] Re-run the documented checks from a fresh checkout in the supported environment.
- [ ] Review any final Lean theorem and its axioms before changing formal-proof claims.
- [ ] Resolve and retain third-party notices for any additional historical archive.
- [ ] Review privacy and metadata recursively before attaching large release assets.
- [ ] Obtain external mathematical/software scrutiny; do not describe internal tests as peer review.
- [ ] Add an actual arXiv identifier or DOI only after one is assigned.
- [ ] Create a tagged release and retain its manifest/ZIP digest in an independent archive.

Do not upload the entire research workspace. It contains caches, exploratory
runs, private filesystem paths and duplicated historical snapshots. Keep large
proof artifacts separate from the curated Git tree; an asset's presence alone
does not make it verified, portable or licensed for redistribution.
